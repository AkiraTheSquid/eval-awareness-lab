# logit-monitor

## Purpose
- Lesson pages for ARENA course unit `lm-1`, "Logit monitor for evaluation awareness (Goodfire 2026)":
  the eight code concepts a learner needs before writing the replication from scratch.

## Owns
- The eight `kp-*.md` pages of the `monitor.*` concepts, as served by the lesson viewer.

## Does NOT own
- The page SOURCE. Pages are GENERATED by `scripts/logit_monitor_course/build.py --apply` from the
  `kc*.py` modules there. Edit those, never these files.
- The conceptual (no-code) half of the topic: Study module `arena-eval-awareness`
  (`This-Directory-Only/courses-private/arena-eval-awareness/`).
- Drills, registry rows, atoms: bank CSV, `kc_registry.json`, `arena_drillable_v1.json`.

## Key Files
- `kp-next-token-logits.md`: row p of the logits scores the token at p + 1; rows for a phrase.
- `kp-forced-logprob.md`: `log_softmax` over the vocabulary, sum over phrase tokens.
- `kp-forced-sequence.md`: prefix + reasoning so far + phrase; tokenise the phrase in context.
- `kp-reasoning-boundaries.md`: cut a rollout at its first stop token; sentence boundaries.
- `kp-padded-batch.md`: right padding, attention mask, per-row phrase rows.
- `kp-prompt-score.md`: minus-infinity padding; max over the first k rollouts.
- `kp-auroc.md`: AUROC as pair wins with half-credit ties; bootstrap interval.
- `kp-baselines.md`: verbalisation baseline; control phrase and prompt-length checks.
- `watch.py`: pages exist, are registered, carry asserted cells.

## Data & External Dependencies
- `../kc_registry.json` (lesson `lm-1`, eight `monitor.*` rows), `../lessons_structured.json`.
- Question ids 1815-1902 in the bank (`pipeline/curated_additions.csv`).

## How It Works (Flow)
1. `build.py --apply` renders each page: frontmatter with rung id lists, two segments
   (concept, worked example, one faded stub), Solo, Integrated, misconceptions.
2. `scripts/compile_lessons.py` compiles them into `lessons_structured.json`.

## Invariants & Constraints
- Every runnable fence ends in `# Hidden checks` with assertions. Hugging Face calls that need
  a real model sit in `python no-run` fences.
- Code lines in fences are at most 54 columns (validator WIDTH).
- Drills are tensor-only on tiny tensors; no model download is ever needed to practise.
- Two segments per page, one idea each. Only ONE faded stub per segment (rung retired).

## Extension Points
- New concept: add `kcN_<slug>.py` in `scripts/logit_monitor_course/`, list it in `KC_MODULES`,
  add its row to `wiring.py`, then `--check`, `--apply` and the gate pipeline in that README.
